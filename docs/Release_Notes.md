# dy下载器（Muse996）更新记录

本项目在开源项目 DouK-Downloader V5.8 的基础上修改，以下只记录本定制版自己的改动。

## 下一版（v5.8.1003，待发布 — 先在本地攒着，等确认完美后一次性发布）

1. 修复两个不同作品被塞进同一个文件夹：文件夹名默认只有日期和类型，同一作者同一天的两个同类作品（如两条实况）会撞成同一个文件夹名；现在先下的保留原名，撞名的自动在文件夹名后加标题区分，标题也一样（或都是无标题）时再加作品 ID；分不同批次下载也不会再合并到一起，同一作品补下仍回它自己的文件夹。已经下好的旧文件不动
2. 拉取列表（收藏、账号作品、合集等）时，进度提示会实时显示“已获取多少条、第几页”，数据量大、拉得久时也能看出程序在干活，不会误以为卡死
3. 终端的采集功能菜单删掉四个采集数据的功能（采集作品评论数据、采集账号详细数据、采集搜索结果数据、采集抖音热榜数据），菜单从 11 项减到 7 项，剩下的全是下载功能；批量下载收藏作品顺延为第 5 项

## 2026-11-08（v5.8.1002）

1. 批量下载收藏作品（终端功能 9）不再因为没填主页链接就直接退出：现在会提示粘贴你自己的抖音主页链接，校验通过后自动保存到配置文件，以后就不用再填了；粘贴的链接取不到账号时会提醒重贴，直接回车可以取消

## 2026-11-07（v5.8.1001）

1. 作者没有写任何描述的作品，文件名（和开启标题时的文件夹名）的标题位置不再显示作品 ID 那串长数字，改为显示“无标题”；同一批里有多个同名作品撞名时，后下的会自动在名字后追加作品 ID 区分，避免被误当成已存在的文件跳过

## 2026-11-07（v5.8.1000）

1. 修复误报“未全部下载完成”：文件实际保存的后缀与计划不一致时（如背景音乐计划存 .mp3、平台实际给的是其他格式），已下载成功的作品也会被误判没下完、且不写下载记录；现在按文件名判断（不卡后缀），下齐了就正常记入下载记录
2. 下载被平台拒绝（403）时不再反复重试，结尾单独提示“被平台拒绝下载（403），可能是仅朋友可见等权限限制，无法下载”；出错信息里去掉了误显示的 TikTok 提示文字（本程序只下载抖音）
3. 退出程序时，后台参数更新请求超时不再往屏幕上打红色错误（仍会记进日志文件）

## 2026-11-07（v5.8.999）

1. 主菜单「删除作品下载记录」改为「删除作者下载记录」：从作者列表里选序号，一次清掉该作者的全部下载记录，他的作品即可重新下载；列表末尾附带“清空全部下载记录”
2. 下载记录现在会同时保存作者信息，删除时才能按作者查找；旧版本下载的作品没有作者信息，不会出现在作者列表里，只能用“清空全部下载记录”处理

## 2026-11-07（v5.8.998）

1. 修复程序中途退出（闪退、断网）后，没下载完整的作品被误记为已下载、再次下载时被整部跳过的问题：下载记录改为整部作品全部文件下载成功后才写入
2. 已经存在这类残缺记录的作品，再次下载时会自动识别并补下缺失的文件，不用手动清理记录

## 2026-11-07（v5.8.997）

1. 文件名和文件夹名的开关分开设置，互不影响（在主菜单「下载规则设置」的问题四、问题五里调）
2. 两边默认都不带作品 ID，命名排版恢复为和原项目一致的清爽样式：文件名是日期-类型-作者-标题-序号，文件夹名是日期-类型

## 2026-11-07（v5.8.996）

1. 删除 TikTok（海外版）的全部下载功能，只保留抖音下载
2. 删除后台监听模式
3. 删除 Web API 模式（Web UI 模式保留，尚未开发完成）

## 2026-11-07（定制版主要改动汇总）

1. 新增自定义下载规则：
   - 图集达到设定张数（默认 2 张）：单独建文件夹，图片和背景音乐放在一起
   - 实况照片按图集处理：单独建文件夹，并下载背景音乐（实况本身没有声音，声音就是背景音乐）
   - 纯视频：直接放在下载根目录，不建文件夹，不下载背景音乐
2. 主菜单新增「下载规则设置」：图片张数门槛、实况存法、视频存法、文件夹名开关、文件名开关，都可以在里面调整，标准开/关措辞，修改后立即生效
3. 文件名和文件夹名都会标注作品类型（图集 / 实况 / 视频）
4. 修复文件夹名过长导致 Windows 路径超限、保存文件时报错的问题
5. 图集背景音乐增加备用下载地址；平台没有提供可下载的背景音乐地址时，会给出明确提醒
6. 修复已经下载过的作品再次下载时重复下载背景音乐的问题
7. 修复已经下载过的作品被跳过时，仍然生成空文件夹的问题
